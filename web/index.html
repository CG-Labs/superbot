A custom role is a base role (member or read-only) plus permissions an admin gives away; it never adds up to admin. Given across the server, its base becomes the person's role. Given within a team, only its team permissions apply, there. Changes apply at once and are audited.

Requests for roles

People ask for a requestable, time-bound role with a reason (ADR 0209). Approve it for as long as asked or shorter, from now; it ends by itself. Nobody decides their own. Undecided requests lapse in 7 days.

A service account is a script's or integration's own identity. It holds member, read-only or a custom role, across the server or within a team, never admin and never more than its owner holds now. It can't sign in and takes no seat; it acts only through tokens shown once, which always expire and can be rotated or revoked. Everything it does is audited as itself.

Rules for all Bots

Deny rules refuse a matching call whatever else is set; allow rules skip asking but never override a class set to Deny. Patterns match the command, path, or address: * is any text, ? one character. Each Bot's own settings and rules are in the app.
